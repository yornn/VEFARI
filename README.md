# VEFARI

Минимальный гардероб для **SillyTavern**, без собственного генератора изображений.
Версия **0.7.0**: перо, которое пишет описание вещи по её картинке, — плюс оформление «Винтерфелл» в духе Севера и викингов, оружейная со слотами надетого, вкладки User / Char, настройки внутри окна, обмен нарядами через PNG со вшитым описанием и отправка картинок нарядов в генератор notsosillynotsoimages.

## Что работает

- Две глобальные коллекции вещей: **User** для пользователей и **Char** для персонажей. У вещи есть название, описание и **необязательная** картинка.
- Вход через **волшебную палочку возле поля ввода → VEFARI** с эмблемой-фибулой. Собственной панели в верхних настройках расширений нет; запись в штатном списке установленных расширений SillyTavern остаётся для управления установкой.
- Наряды отдельно для персонажа и пользователя.
- Два режима: полный наряд или верх / низ / обувь. Аксессуары и причёска доступны в обоих режимах.
- Выбор вещей сохраняется отдельно для каждой карточки персонажа.
- Надетые вещи автоматически включаются в системный блок `OUTFIT` на глубине `0`, без названия расширения в тексте для модели.
- Инжект обновляется при смене чата, изменении вещей и перед генерацией ответа, в том числе свайпом и регенерацией.
- Выключение гардероба сразу очищает инжект, не удаляя коллекцию.
- Редактирование и удаление вещей, замена и удаление их картинок.
- Экспорт наряда из редактора: скачивается PNG, в который вшит текст описания (стандартный чанк `iTXt`, без категорий и коллекций — их выбирает получатель).
- Импорт наряда пустой карточкой «Импорт PNG» в начале коллекции: PNG со вшитым описанием открывается в редакторе с заполненным текстом, названием из имени файла и превью картинки.
- Кнопка «Экспорт всех нарядов» в настройках: ZIP-архив с картинкой каждой вещи, описание вшито в свой PNG; текстовые вещи получают нарисованную карточку-заглушку.
- Просмотр текста текущего инжекта.
- **Перо** в редакторе вещи пишет описание по картинке: отдельный промпт для каждой категории, через профиль подключения SillyTavern (меню с розеткой) или через свой OpenAI-совместимый адрес и ключ.
- Картинки и описания надетых вещей добавляются в запрос расширения [notsosillynotsoimages](https://github.com/aceeenvw/notsosillynotsoimages) в момент генерации картинки (API Type: Gemini-compatible).

VEFARI занимается только гардеробом: хранит вещи, сообщает модели, что надето
на участниках чата, и подкладывает наряды в запрос генератора картинок.
Собственная генерация изображений, галерея и NPC-референсы
не входят в эту версию.

## Установка

В SillyTavern откройте **Расширения → Установить расширение** и укажите:

```text
https://github.com/yornn/VEFARI
```

Установка по ссылке доступна после публикации этих файлов в репозитории.
Для локальной установки поместите папку VEFARI со всеми файлами в каталог
сторонних расширений вашей установки SillyTavern и перезагрузите страницу.
Сборка, `npm install`, Extras и отдельный сервер не нужны.

## Использование

### Оформление «Винтерфелл»

Окно оформлено в духе Севера из «Игры престолов» и викингов: холодное железо
и иней на непрозрачном ночном фоне с тихой фактурой камня, прямые углы, тонкие
линии и двойные рамки вместо скруглений, уголки-скобы по краям окна. Эмблема —
кованая кольцевая фибула (застёжка плаща) с иглой по диагонали; рядом с названием
стоит VEFARI, записанное рунами старшего футарка (ᚹᛖᚠᚨᚱᛁ). Все иконки, фибула
и руны нарисованы для VEFARI в SVG и не требуют внешних файлов.

Цвета работают по ролям: **иней** — всё выбранное (надетая вещь, активная вкладка,
слот и чип фильтра, фокус клавиатуры), **сталь** — одна главная кнопка на экране,
**кровь** — только удаление и ошибки. Надетая вещь получает рамку и «изморозь» инея,
а заодно появляется в своём слоте оружейной. Внутренний интерфейс изолирован через Shadow DOM,
поэтому CSS тем SillyTavern не переоформляет его элементы. Штатная оболочка Popup
имеет отдельные защитные стили; намеренные правила, нацеленные на сам `#vefari_dialog`,
или фильтры на родительских элементах страницы могут повлиять на всё окно.
Пункт меню волшебной палочки (малая фибула и слово VEFARI) остаётся частью темы Tavern.

Шрифты загружаются с **Google Fonts**: **Forum** — логотип, заголовки и названия вещей,
**Alegreya Sans SC** — капитель вкладок, слотов и чипов, **Alegreya Sans** — основной текст.
При недоступности Google Fonts используются Georgia / Segoe UI / системные шрифты;
гардероб остаётся рабочим. Запросы шрифтов идут к `fonts.googleapis.com` и
`fonts.gstatic.com`, данные гардероба в них не передаются.

### Работа с гардеробом

Окно делится на две колонки. Слева **оружейная**: вкладки **User** и **Char** с именами
участников чата, переключатель **«Целиком / По частям»** и слоты надетого. В режиме
«Целиком» видны слоты «Полный наряд», «Аксессуары», «Причёска», в режиме «По частям» —
«Верх», «Низ», «Обувь», «Аксессуары», «Причёска». Справа — **коллекция** выбранной вкладки.
На узком экране оружейная складывается в блок над коллекцией, а слоты и чипы
становятся прокручиваемыми строками.

1. Нажмите **волшебную палочку возле ввода сообщения → VEFARI** и выберите вкладку **User** или **Char**.
2. Коллекция всегда начинается с двух пустых карточек. Нажмите **«Новая вещь»** (с плюсом): в редакторе задайте название, коллекцию (User / Char / Оба), категорию и описание. Если коллекция отфильтрована по категории, новая вещь сразу получает её. Вторая пустая карточка, **«Импорт PNG»**, принимает PNG со вшитым описанием наряда (например, выгруженный через экспорт в редакторе вещи) и открывает редактор с готовыми текстом и картинкой — остаётся выбрать категорию и сохранить.
3. При желании перетащите в зону картинки или выберите PNG, JPEG или WebP размером до 10 МБ — картинка сразу видна в зоне. Если название ещё не заполнено, оно подставится из имени файла — впечатанное вами название картинка не перезаписывает. У сохранённой картинки под зоной есть кнопки **«Заменить»** и **«Убрать»**.
4. Если писать описание не хочется, нажмите **перо** справа от подписи «Описание для модели»: оно отправит картинку модели и впишет описание для выбранной категории. Повторное нажатие останавливает запрос. Подключение для пера выбирается в настройках — см. «[Описание по картинке](#описание-по-картинке-перо)».
5. Переключатель **«Картинка и текст / Только текст»** выбирает, что отправлять в генератор картинок: описание попадает в чат всегда, а картинка — только в режиме «Картинка и текст». Одной вещи достаточно — дублировать текстовый и полный варианты не нужно.
6. Сохраните вещь и **нажмите на её карточку**, чтобы надеть её; повторный клик по надетой карточке снимает вещь. Для надевания должен быть открыт одиночный чат. Надетая вещь появляется в своём слоте оружейной; крестик в слоте снимает её, а **клик по самому слоту** показывает в коллекции только вещи этой категории. Чипы над коллекцией делают то же для любой категории, «Все» сбрасывает фильтр.
7. **Шестерёнка справа сверху** открывает настройки во всю ширину окна: руны-переключатели ᛉ «Гардероб включён» и «Картинки нарядов в генератор», лимит картинок со степпером, экспорт всех нарядов, подключение для пера и текст текущего инжекта. Если гардероб выключен, в оружейной появляется плашка с кнопкой «Включить». Кнопка «К нарядам» возвращает к коллекции.

Карточка вещи показывает только картинку, название и — при наведении — кнопки «изменить» и «удалить» поверх картинки (на сенсорных экранах они видны всегда). Вещь без картинки показывает иконку своей категории. Длинные названия обрезаются до двух строк, полное видно во всплывающей подсказке. Экспорт PNG со вшитым описанием доступен в редакторе вещи с картинкой.

Коллекции не привязаны к именам: во всех чатах видны одни и те же вещи User и Char.
Отдельно хранится **выбор надетого** для каждой карточки персонажа — смена бота не
переносит на него одежду автоматически. Окно можно закрыть крестиком или Escape;
инжект продолжает работать. Несохранённая форма требует подтверждения перед закрытием
или сменой вкладки; пока открыт редактор, оружейная неактивна. Вкладки также переключаются стрелками, Home и End.

Картинка не обязательна: текстовый гардероб работает без генерации изображений
и без мультимодальной модели. Описание обязательно, потому что именно оно
отправляется в чат. Сама картинка в чат не уходит и не анализируется — описание
по ней пишет только перо, и только когда вы его нажимаете.

При надевании полного наряда включается полный режим; при надевании верха,
низа или обуви — режим по частям. Скрытые выборы другого режима сохраняются,
но не инжектятся. «Снять всё» очищает и видимые, и скрытые слоты выбранного владельца.
Изменение категории вещи снимает её со всех владельцев — после этого наденьте её заново.
Перенос вещи только в User или только в Char снимает её с владельцев другой роли.

**Снять вещь** означает убрать её описание из инжекта, а не отправить модели
команду раздеть персонажа. Перед генерацией модель получает описание текущего
выбора в гардеробе, но это не гарантирует послушание любой модели или пресета.

Каждый одетый участник получает отдельный однострочный блок, без JSON и служебных пояснений:

```text
[OUTFIT: Петя is currently wearing: FULL: Льняная рубашка, тёмные брюки и кожаные сапоги.]
[OUTFIT: Маша is currently wearing: FULL: Зелёное платье. HAIR: Длинные тёмные волосы.]
```

Категории обозначаются как `FULL`, `TOP`, `BOTTOM`, `SHOES`, `ACCESSORIES`, `HAIR`.
Переносы строк в описаниях объединяются пробелами, внутренние квадратные скобки
заменяются круглыми только в промпте — сохранённые описания не меняются.
Если для участника ничего не выбрано, его блок отсутствует.

## Описание по картинке (перо)

Перо в редакторе вещи отправляет картинку модели, которая умеет смотреть изображения,
и вписывает ответ в поле «Описание для модели». Описание остаётся черновиком: его можно
поправить, а в коллекцию оно попадёт только после «Сохранить вещь». Если поле уже
заполнено, перо сначала спросит, заменить ли текст.

Для каждой категории свой англоязычный промпт (`outfit-prompts.js`), и модель описывает
только свою часть:

- **Полный наряд** — одежда со слоями и отделкой, обувь, оружие и вещи в руках, аксессуары и мелочи. Внешность (волосы и причёска, лицо, борода, кожа, шрамы, телосложение) не описывается.
- **Верх**, **Низ**, **Обувь**, **Аксессуары** — только своя часть; оружие относится к аксессуарам.
- **Причёска** — длина, цвет, фактура, укладка и украшения в волосах, без лица и бороды.

Ответ — одна строка английского текста в стиле каталога, например
`black molded-leather muscle cuirass with gold-trimmed edges … and hanging black belt strap`.
Если на картинке нет ничего для выбранной категории (скажем, ноги обрезаны, а категория
«Обувь»), модель отвечает `NO_OUTFIT`, и перо сообщает об этом вместо того, чтобы вписать мусор.

### Подключение

Настройки → блок **«Описание по картинке»** → список **«Подключение для пера»**:

- **Профиль подключения** — любой профиль Chat Completion из меню с розеткой SillyTavern
  (Connection Manager). Запрос уходит через SillyTavern с моделью, ключом, прокси и пресетом
  этого профиля. Профили Text Completion в списке не показываются: они не принимают картинки.
- **Свой адрес и ключ** — OpenAI-совместимый адрес вида `https://api.example.com/v1`
  (если вставить адрес с `/chat/completions`, хвост отрежется), ключ и модель.
  «Проверить и загрузить модели» запрашивает список моделей и заодно проверяет адрес и ключ.
  Без ключа запрос уходит без авторизации — так работают локальные модели.

Модель обязательно должна видеть картинки (например, Gemini, GPT-4o, Claude, Qwen-VL,
LLaVA). Текстовая модель вернёт ошибку или выдумку.

### Где хранятся данные и куда они уходят

- VEFARI не читает и не хранит ключи профилей: в настройках гардероба лежит только идентификатор выбранного профиля, ключ остаётся в SillyTavern.
- Свой ключ хранится **только в этом браузере** (`localStorage`, запись `vefari_describer_key`) и никогда не попадает в `extensionSettings`, `settings.json`, экспорт нарядов или на экран: поле ключа очищается сразу после ввода. На другом устройстве или в другом браузере ключ нужно ввести заново.
- Ключ привязан к адресу (схема, хост и порт), для которого его ввели. Смена адреса на другой хост удаляет ключ из браузера, поэтому он не может уйти туда, куда его не вводили. Адрес с логином, паролем или параметрами после `?` не принимается — ключ вводится только в поле «Ключ».
- Запрос идёт с вашей страницы на ваш же сервер SillyTavern, а с него — на выбранный адрес. Ключ передаётся в собственном заголовке `Authorization` этого запроса. Сохранённые ключи SillyTavern при этом не читаются: запрос нарочно указывает несуществующий идентификатор секрета, иначе сервер подставил бы ваш активный ключ Custom.
- Модели уходят только картинка редактируемой вещи и промпт её категории. Ни чата, ни карточки персонажа, ни других вещей в запросе нет.

## Картинки и генераторы

### Мост к notsosillynotsoimages

VEFARI сам ничего не генерирует. Когда расширение
[notsosillynotsoimages](https://github.com/aceeenvw/notsosillynotsoimages)
отправляет запрос на картинку, VEFARI в этот момент дописывает в него надетые вещи.
Работает только при **API Type: Gemini-compatible** в настройках генератора;
сам генератор не меняется и обновляется как обычно.

- **Чей наряд уходит.** Так же, как генератор решает, слать ли лицо: имя персонажа
  или юзера есть в промпте картинки (с алиасами через запятую из имени слота
  генератора) либо у слота включено «always». Пейзаж без людей уходит без нарядов.
- **Картинкой** уходит вещь, если включены «Картинки нарядов в генератор»
  в настройках VEFARI, у вещи выбран режим «Картинка и текст», у неё есть картинка
  и в генераторе не выключено «Send refs» для Gemini. Каждая картинка идёт отдельно
  с подписью, чья это вещь и какая категория, и указанием одеть именно в неё.
- **Текстом** уходят все надетые вещи прошедших участников: блок `[OUTFIT: …]`
  дописывается в начало промпта картинки — сразу после инструкции генератора
  «копируй внешность с референсов», чтобы последнее слово про одежду было за нарядом.
- **Лимит** «Максимум картинок нарядов» (1–10, по умолчанию 4) общий на запрос:
  сначала Char, потом User, по порядку категорий. Вещи сверх лимита уходят только
  описанием. Генератор сам добавляет до 4 своих референсов (лица, NPC), поэтому
  для моделей, которые принимают мало картинок, лимит лучше уменьшить.
- **Что ушло** видно в настройках VEFARI, в блоке «Генератор картинок»: «Последняя отправка:
  Маша — 2 картинки, 1 текстом». Подробно — DevTools → Network → запрос
  `…:generateContent` → тело: части с подписью `Outfit reference for …` и `inlineData`.
- Если картинка вещи недоступна, вещь уходит описанием. Любая ошибка моста
  отправляет исходный запрос генератора без изменений: генерация не ломается.

Ограничения моста:

- Поддерживается только Gemini-compatible; OpenAI-compatible и Naistera пока нет.
- Если провайдер вернул пустой ответ, генератор повторяет запрос без своих
  референсов, а VEFARI добавит наряды и в повтор.
- VEFARI читает настройки генератора (`extensionSettings.inline_image_gen`) и
  ничего в них не пишет. Если автор генератора переименует их, мост отключится,
  а в окне VEFARI появится сообщение об этом.
- Для перехвата VEFARI оборачивает `window.fetch` и `XMLHttpRequest` (второй нужен
  генератору на iOS). Остальные запросы уходят без изменений.

### JavaScript API для других адаптеров

```js
// Снимок активного гардероба в текущем одиночном чате.
const outfits = window.vefari.getActiveOutfits();
// null, если нет выбранного персонажа или открыт групповой чат.
// Иначе: { enabled, characterKey, characterName, userName,
//          bot: { description, items }, user: { description, items } }

// Загружает картинки видимых активных слотов выбранного владельца.
const references = await window.vefari.getImageReferences('bot'); // либо 'user'
// Массив: { id, name, category, description, imagePath, audiences, sendImage, mimeType, base64 }.
// Возвращаются только вещи в режиме «Картинка и текст» (sendImage);
// вещи в режиме «Только текст» пропускаются, их описание всё равно в инжекте.
// base64 — содержимое без префикса data:. Функция не вызывает генератор.
```

У выключенного гардероба описания и массивы вещей пустые, референсы не загружаются.
API возвращает копии вещей, не позволяя случайно менять сохранённую коллекцию.
Ошибка чтения референса отклоняет Promise: адаптер должен её обработать.
Коллажи не собираются; ограничения количества референсов и формата запроса
должен учитывать адаптер выбранного генератора.

## Хранение и ограничения первой версии

- Метаданные сохраняются штатным механизмом настроек SillyTavern в `extensionSettings.vefari`. Подключение пера — поле `describer` с четырьмя значениями: источник, идентификатор профиля, адрес и модель. Остальные поля, в том числе случайно попавший туда ключ, отбрасываются при чтении и записи.
- Ключ своего адреса для пера хранится только в `localStorage` браузера (см. «[Где хранятся данные](#где-хранятся-данные-и-куда-они-уходят)»).
- Формат данных версии 3: каталог `items` с полем `audiences` (`user` / `bot` или обе роли) и список назначений `assignments` с владельцем, режимом и идентификаторами вещей. Каждая команда создаёт новое состояние, не изменяя предыдущее.
- Данные VEFARI 0.1 / 0.2 читаются автоматически. Старые вещи без разделения коллекций доступны в обеих вкладках, без потери надетых нарядов. При первом изменении создаётся резервная копия `extensionSettings.vefari_v1_backup` или `extensionSettings.vefari_v2_backup`, затем сохраняется новая схема. Повреждённые и неизвестные версии не перезаписываются; инжект очищается, ошибка показывается в окне.
- Картинки сохраняются через `/api/images/upload` в пользовательской директории изображений, в отдельной подпапке `vefari_refs`; base64 не хранится в настройках.
- Картинки нормализуются в PNG и уменьшаются до 1024 пикселей по длинной стороне.
- При замене или удалении картинки старый файл удаляется, только если больше не используется коллекцией VEFARI или резервной копией миграции. Чужие папки расширение не трогает. Ошибка удаления файла показывается в панели и не отменяет сохранённый текст.
- Выбор привязан к имени файла аватара карточки, а не к отображаемому имени или индексу в списке. Одноимённые карточки не смешиваются. Если SillyTavern переименует сам файл карточки, выбор понадобится назначить заново.
- Выбор общий для всех чатов одной карточки. История смены одежды, откаты со свайпами и отдельные наряды для разных пользовательских персон пока не реализованы.
- Групповые чаты пока не поддерживаются: инжект в них очищается.
- Обмен нарядами идёт только через PNG со вшитым описанием; прямого импорта коллекций других расширений нет. Из генераторов поддержан только notsosillynotsoimages (Gemini-compatible). Не включайте несколько текстовых гардеробов одновременно, если их инструкции могут противоречить друг другу.
- Используются `SillyTavern.getContext()`, `setExtensionPrompt`, события генерации, штатные endpoints изображений и обёртки `fetch` / `XMLHttpRequest` для моста к генератору. Совместимость с вашей версией SillyTavern следует проверить вручную; локальные автоматические тесты не заменяют эту проверку.

## Устройство

- Ядро принимает команды добавления, изменения, удаления и выбора вещей; не обращается к браузеру или SillyTavern.
- Адаптер хранения проверяет структуру данных и переносит настройки ранней версии.
- Построитель промпта отделён от хранения: формирует отдельные блоки `[OUTFIT: имя is currently wearing: FULL: описание. HAIR: описание.]`. Изображения и внутренние пути в текст не попадают. Квадратные скобки обозначают границы блока, но не являются защитой от интерпретации текста моделью как инструкции.
- Контроллер сохраняет состояние, обновляет единственный системный блок и уведомляет интерфейс. Подписки на события можно отключить без оставшегося инжекта.
- Медиа-адаптер работает со штатными HTTP endpoints SillyTavern; генератор не вызывается.
- Мост к генератору: `generator.js` только читает настройки notsosillynotsoimages, `bridge.js` без зависимостей от браузера опознаёт его запрос, решает, что слать, и собирает новое тело, `interceptor.js` оборачивает `fetch` и `XMLHttpRequest`. При ошибке уходит исходный запрос.
- Модуль обмена вшивает описание в PNG чанком `iTXt` с ключом `vefari` (UTF-8, без сжатия) и собирает ZIP без сторонних библиотек; при импорте читается также общий ключ `Description`. Картинка при этом не перекодируется.
- Окно использует штатный `Popup` SillyTavern; при закрытии его содержимое отсоединяется и сохраняет обработчики для повторного открытия. SVG-иконки, фибула и руны нарисованы для VEFARI и не требуют внешних шрифтов; контур фибулы строится функцией в `icons.js`, сборка карточек, слотов и чипов вынесена в `render.js`.
- Перо: `outfit-prompts.js` — промпты по категориям, `describe.js` — сборка запроса, отправка через Connection Manager или штатный `ChatCompletionService` SillyTavern и разбор ответа, `keystore.js` — ключ своего адреса в `localStorage` с привязкой к хосту.
- `style.css` оформляет только оболочку Popup и подключает Google Fonts; `wardrobe.css` загружается внутрь Shadow DOM вместе с интерфейсом.

Внешние контракты проверялись по [документации UI Extensions](https://docs.sillytavern.app/for-contributors/writing-extensions/)
и публичному API SillyTavern. Обязательных зависимостей от других расширений нет; notsosillynotsoimages нужен только для моста картинок.

## Проверки для разработки

Node.js 22+; сторонние npm-зависимости не нужны.

```sh
npm run check
npm test
npm run test:browser
```

Браузерная проверка запускает установленный Chrome, Edge или Chromium в headless-режиме.
При необходимости задайте переменную окружения `VEFARI_BROWSER` с абсолютным путём
к браузеру. Тест использует настоящий DOM, canvas, загрузку картинок и HTTP,
но имитирует контекст и серверные endpoints SillyTavern.
Дополнительно проверяет изоляцию от агрессивного CSS темы, собственную подложку,
прямые углы, раскладку оружейной и коллекции, слоты и фильтры, ровные кнопки карточек при длинных названиях, доступные подписи и размеры редактора.
Для пера проверяются выбор профиля, запрос с картинкой и промптом категории, отмена, ответ `NO_OUTFIT`,
хранение ключа только в браузере, его привязка к адресу и отсутствие ключа в настройках SillyTavern;
модели в тесте подменены, настоящие запросы к ИИ не отправляются.
`VEFARI_MOBILE=1` запускает тот же сценарий с шириной 390 пикселей;
`VEFARI_SCREENSHOT` задаёт абсолютный путь для PNG-снимка финального окна.
`VEFARI_SETTINGS_SCREENSHOT` сохраняет дополнительный снимок редактора.
`VEFARI_WIDTH` / `VEFARI_HEIGHT` переопределяют размеры экрана;
`VEFARI_OFFLINE_FONTS=1` блокирует Google Fonts для проверки запасных шрифтов.
Через DevTools также проверяются настоящие Tab, Shift+Tab, Escape, Enter
и возврат фокуса после закрытия окна.

Перо в живом SillyTavern: выберите профиль с моделью, которая видит картинки, создайте вещь с картинкой,
нажмите перо для разных категорий и проверьте в инспекторе запроса, что ушли картинка и промпт категории.

Для проверки в живом SillyTavern: добавьте текстовую вещь и вещь с картинкой,
наденьте их, отправьте сообщение, сделайте свайп, смените персонажа, выключите
гардероб и перезагрузите страницу. Проверьте сохранение данных и итоговый промпт
в инспекторе запроса. Отдельно проверьте, что при выключении старый `vefari_outfit`
пуст, а изменение описания активной вещи видно уже в следующем запросе.
