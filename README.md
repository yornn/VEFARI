# VEFARI

Минимальный гардероб для **SillyTavern**, без собственного генератора изображений.
Версия **0.4.0**: окно гардероба в меню волшебной палочки, вкладки User / Char, настройки внутри окна и обмен нарядами через PNG со вшитым описанием.

## Что работает

- Две глобальные коллекции вещей: **User** для пользователей и **Char** для персонажей. У вещи есть название, описание и **необязательная** картинка.
- Вход через **волшебную палочку возле поля ввода → VEFARI** с SVG-иконкой северной туники. Собственной панели в верхних настройках расширений нет; запись в штатном списке установленных расширений SillyTavern остаётся для управления установкой.
- Наряды отдельно для персонажа и пользователя.
- Два режима: полный наряд или верх / низ / обувь. Аксессуары и причёска доступны в обоих режимах.
- Выбор вещей сохраняется отдельно для каждой карточки персонажа.
- Надетые вещи автоматически включаются в системный блок `OUTFIT` на глубине `0`, без названия расширения в тексте для модели.
- Инжект обновляется при смене чата, изменении вещей и перед генерацией ответа, в том числе свайпом и регенерацией.
- Выключение гардероба сразу очищает инжект, не удаляя коллекцию.
- Редактирование и удаление вещей, замена и удаление их картинок.
- Экспорт наряда из редактора: скачивается PNG, в который вшит текст описания (стандартный чанк `iTXt`, без категорий и коллекций — их выбирает получатель).
- Импорт наряда кнопкой рядом с «+»: PNG со вшитым описанием открывается в редакторе с заполненным текстом, названием из имени файла и превью картинки.
- Кнопка «Экспорт всех нарядов» в настройках: ZIP-архив с картинкой каждой вещи, описание вшито в свой PNG; текстовые вещи получают нарисованную карточку-заглушку.
- Просмотр текста текущего инжекта.

VEFARI занимается только гардеробом: хранит вещи и сообщает модели, что надето
на участниках чата. Генерация изображений, галерея, автоописание и NPC-референсы
не входят в эту версию.

## Установка

В SillyTavern откройте **Расширения → Установить расширение** и укажите:

```text
https://github.com/yornn/VEFARI
```

Установка по ссылке доступна после публикации этих файлов в репозитории.
Для локальной установки поместите папку VEFARI со всеми файлами в каталог
сторонних расширений вашей установки SillyTavern и перезагрузите страницу.
Сборка, `npm install`, Extras и отдельный сервер не нужны.

## Использование

### Оформление

Окно использует собственное северное фэнтези-оформление: непрозрачный угольный фон,
состаренное золото, компактные вкладки и карточки. Вкладки **USER** и **CHAR**
показывают актуальные имена участников чата. Надетая вещь помечается золотой
обводкой-подсветкой без лишних подписей. Внутренний интерфейс изолирован
через Shadow DOM, поэтому CSS тем SillyTavern не переоформляет его элементы.
Штатная оболочка Popup имеет отдельные защитные стили; намеренные правила,
нацеленные на сам `#vefari_dialog`, или фильтры на родительских элементах страницы
могут повлиять на всё окно. Пункт меню волшебной палочки остаётся частью темы Tavern.

Шрифты загружаются с **Google Fonts**: **Cinzel** — логотип и латинские вкладки,
**Cormorant Garamond** — заголовки с кириллицей, **Golos Text** — основной текст.
При недоступности Google Fonts используются Georgia / Segoe UI / системные шрифты;
гардероб остаётся рабочим. Запросы шрифтов идут к `fonts.googleapis.com` и
`fonts.gstatic.com`, данные гардероба в них не передаются.

### Работа с гардеробом

1. Нажмите **волшебную палочку возле ввода сообщения → VEFARI** и выберите вкладку **User** или **Char**.
2. Нажмите золотую кнопку **«+»** справа от фильтра. В редакторе задайте название, категорию и описание. По умолчанию вещь сохраняется в текущую вкладку; можно выбрать «User и Char», чтобы она была доступна в обеих. Иконка импорта рядом с «+» принимает PNG со вшитым описанием наряда (например, выгруженный через «Экспорт» в редакторе вещи) и открывает редактор с готовыми текстом и картинкой — остаётся выбрать категорию и сохранить.
3. При желании добавьте PNG, JPEG или WebP размером до 10 МБ. Если название ещё не заполнено, оно подставится из имени файла — впечатанное вами название картинка не перезаписывает.
4. Переключатель **«Картинка и текст / Только текст»** выбирает, что отправлять для этой вещи: описание попадает в чат всегда, а референс через API отдаётся только в режиме «Картинка и текст». Одной вещи достаточно — дублировать текстовый и полный варианты не нужно.
5. Сохраните вещь и **нажмите на её карточку**, чтобы надеть её; повторный клик по надетой карточке снимает вещь. Для надевания должен быть открыт одиночный чат. Надетая вещь выделяется золотой обводкой-подсветкой, а список надетого закреплён панелью «Сейчас надето» внизу окна.
6. **Шестерёнка справа сверху** открывает только настройки в том же окне: включение гардероба, режим выбранного владельца и «Текст текущего инжекта». Редактор вещи — отдельный экран, открываемый кнопкой «+» или иконкой карандаша на карточке. Кнопка «К нарядам» возвращает к коллекции.

Карточка вещи показывает только картинку, название и иконки изменения и удаления — категория и описание живут в редакторе и не создают визуальный шум в коллекции.

Коллекции не привязаны к именам: во всех чатах видны одни и те же вещи User и Char.
Отдельно хранится **выбор надетого** для каждой карточки персонажа — смена бота не
переносит на него одежду автоматически. Окно можно закрыть крестиком или Escape;
инжект продолжает работать. Несохранённая форма требует подтверждения перед закрытием
или сменой вкладки. Вкладки также переключаются стрелками, Home и End.

Картинка не обязательна: текстовый гардероб работает без генерации изображений
и без мультимодальной модели. Описание обязательно, потому что именно оно
отправляется в чат; модель не анализирует загруженную картинку автоматически.

При надевании полного наряда включается полный режим; при надевании верха,
низа или обуви — режим по частям. Скрытые выборы другого режима сохраняются,
но не инжектятся. «Снять всё» очищает и видимые, и скрытые слоты выбранного владельца.
Изменение категории вещи снимает её со всех владельцев — после этого наденьте её заново.
Перенос вещи только в User или только в Char снимает её с владельцев другой роли.

**Снять вещь** означает убрать её описание из инжекта, а не отправить модели
команду раздеть персонажа. Перед генерацией модель получает описание текущего
выбора в гардеробе, но это не гарантирует послушание любой модели или пресета.

Каждый одетый участник получает отдельный однострочный блок, без JSON и служебных пояснений:

```text
[OUTFIT: Петя is currently wearing: FULL: Льняная рубашка, тёмные брюки и кожаные сапоги.]
[OUTFIT: Маша is currently wearing: FULL: Зелёное платье. HAIR: Длинные тёмные волосы.]
```

Категории обозначаются как `FULL`, `TOP`, `BOTTOM`, `SHOES`, `ACCESSORIES`, `HAIR`.
Переносы строк в описаниях объединяются пробелами, внутренние квадратные скобки
заменяются круглыми только в промпте — сохранённые описания не меняются.
Если для участника ничего не выбрано, его блок отсутствует.

## Картинки и генераторы

**VEFARI пока не отправляет картинки ни в чат-модель, ни в генератор автоматически.**
Оно хранит референсы и предоставляет JavaScript API для отдельного адаптера генератора.
Текст наряда уже попадает в обычный запрос и может учитываться при написании
моделью текстовой подсказки для изображения.

```js
// Снимок активного гардероба в текущем одиночном чате.
const outfits = window.vefari.getActiveOutfits();
// null, если нет выбранного персонажа или открыт групповой чат.
// Иначе: { enabled, characterKey, characterName, userName,
//          bot: { description, items }, user: { description, items } }

// Загружает картинки видимых активных слотов выбранного владельца.
const references = await window.vefari.getImageReferences('bot'); // либо 'user'
// Массив: { id, name, category, description, imagePath, audiences, sendImage, mimeType, base64 }.
// Возвращаются только вещи в режиме «Картинка и текст» (sendImage);
// вещи в режиме «Только текст» пропускаются, их описание всё равно в инжекте.
// base64 — содержимое без префикса data:. Функция не вызывает генератор.
```

У выключенного гардероба описания и массивы вещей пустые, референсы не загружаются.
API возвращает копии вещей, не позволяя случайно менять сохранённую коллекцию.
Ошибка чтения референса отклоняет Promise: адаптер должен её обработать.
Коллажи не собираются; ограничения количества референсов и формата запроса
должен учитывать адаптер выбранного генератора.

## Хранение и ограничения первой версии

- Метаданные сохраняются штатным механизмом настроек SillyTavern в `extensionSettings.vefari`.
- Формат данных версии 3: каталог `items` с полем `audiences` (`user` / `bot` или обе роли) и список назначений `assignments` с владельцем, режимом и идентификаторами вещей. Каждая команда создаёт новое состояние, не изменяя предыдущее.
- Данные VEFARI 0.1 / 0.2 читаются автоматически. Старые вещи без разделения коллекций доступны в обеих вкладках, без потери надетых нарядов. При первом изменении создаётся резервная копия `extensionSettings.vefari_v1_backup` или `extensionSettings.vefari_v2_backup`, затем сохраняется новая схема. Повреждённые и неизвестные версии не перезаписываются; инжект очищается, ошибка показывается в окне.
- Картинки сохраняются через `/api/images/upload` в пользовательской директории изображений, в отдельной подпапке `vefari_refs`; base64 не хранится в настройках.
- Картинки нормализуются в PNG и уменьшаются до 1024 пикселей по длинной стороне.
- При замене или удалении картинки старый файл удаляется, только если больше не используется коллекцией VEFARI или резервной копией миграции. Чужие папки расширение не трогает. Ошибка удаления файла показывается в панели и не отменяет сохранённый текст.
- Выбор привязан к имени файла аватара карточки, а не к отображаемому имени или индексу в списке. Одноимённые карточки не смешиваются. Если SillyTavern переименует сам файл карточки, выбор понадобится назначить заново.
- Выбор общий для всех чатов одной карточки. История смены одежды, откаты со свайпами и отдельные наряды для разных пользовательских персон пока не реализованы.
- Групповые чаты пока не поддерживаются: инжект в них очищается.
- Обмен нарядами идёт только через PNG со вшитым описанием; прямого импорта коллекций других расширений и автоматического подключения к генераторам нет. Не включайте несколько текстовых гардеробов одновременно, если их инструкции могут противоречить друг другу.
- Используются `SillyTavern.getContext()`, `setExtensionPrompt`, события генерации и штатные endpoints изображений. Совместимость с вашей версией SillyTavern следует проверить вручную; локальные автоматические тесты не заменяют эту проверку.

## Устройство

- Ядро принимает команды добавления, изменения, удаления и выбора вещей; не обращается к браузеру или SillyTavern.
- Адаптер хранения проверяет структуру данных и переносит настройки ранней версии.
- Построитель промпта отделён от хранения: формирует отдельные блоки `[OUTFIT: имя is currently wearing: FULL: описание. HAIR: описание.]`. Изображения и внутренние пути в текст не попадают. Квадратные скобки обозначают границы блока, но не являются защитой от интерпретации текста моделью как инструкции.
- Контроллер сохраняет состояние, обновляет единственный системный блок и уведомляет интерфейс. Подписки на события можно отключить без оставшегося инжекта.
- Медиа-адаптер работает со штатными HTTP endpoints SillyTavern; генератор не вызывается.
- Модуль обмена вшивает описание в PNG чанком `iTXt` с ключом `vefari` (UTF-8, без сжатия) и собирает ZIP без сторонних библиотек; при импорте читается также общий ключ `Description`. Картинка при этом не перекодируется.
- Окно использует штатный `Popup` SillyTavern; при закрытии его содержимое отсоединяется и сохраняет обработчики для повторного открытия. SVG-иконки нарисованы для VEFARI и не требуют внешних шрифтов.
- `style.css` оформляет только оболочку Popup и подключает Google Fonts; `wardrobe.css` загружается внутрь Shadow DOM вместе с интерфейсом.

Внешние контракты проверялись по [документации UI Extensions](https://docs.sillytavern.app/for-contributors/writing-extensions/)
и публичному API SillyTavern. Зависимостей от других расширений нет.

## Проверки для разработки

Node.js 22+; сторонние npm-зависимости не нужны.

```sh
npm run check
npm test
npm run test:browser
```

Браузерная проверка запускает установленный Chrome, Edge или Chromium в headless-режиме.
При необходимости задайте переменную окружения `VEFARI_BROWSER` с абсолютным путём
к браузеру. Тест использует настоящий DOM, canvas, загрузку картинок и HTTP,
но имитирует контекст и серверные endpoints SillyTavern.
Дополнительно проверяет изоляцию от агрессивного CSS темы, собственную подложку,
компактность вкладок, фильтра и карточек, доступные подписи и размеры редактора.
`VEFARI_MOBILE=1` запускает тот же сценарий с шириной 390 пикселей;
`VEFARI_SCREENSHOT` задаёт абсолютный путь для PNG-снимка финального окна.
`VEFARI_SETTINGS_SCREENSHOT` сохраняет дополнительный снимок редактора.
`VEFARI_WIDTH` / `VEFARI_HEIGHT` переопределяют размеры экрана;
`VEFARI_OFFLINE_FONTS=1` блокирует Google Fonts для проверки запасных шрифтов.
Через DevTools также проверяются настоящие Tab, Shift+Tab, Escape, Enter
и возврат фокуса после закрытия окна.

Для проверки в живом SillyTavern: добавьте текстовую вещь и вещь с картинкой,
наденьте их, отправьте сообщение, сделайте свайп, смените персонажа, выключите
гардероб и перезагрузите страницу. Проверьте сохранение данных и итоговый промпт
в инспекторе запроса. Отдельно проверьте, что при выключении старый `vefari_outfit`
пуст, а изменение описания активной вещи видно уже в следующем запросе.
